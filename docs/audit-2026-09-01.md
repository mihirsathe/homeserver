## P1 — Backups and Recovery

- [ ] The `backups` share has no `/boot/config/shares/backups.cfg`; Unraid treats it as cache-only, the mover ignores it, and all 14 GB of archives plus both Nextcloud pg_dumps live on `/mnt/cache`. One pool failure loses source and copy. Fix: create the share in GUI with primary storage = array (cache: no), move existing archives to the array, set `BACKUP_REMOTE`.

- [ ] `scripts/restore-appdata.sh` (lines 116-131) expects `appdata/<svc>/` inside one archive; the Appdata Backup plugin writes one tarball per container with absolute paths. Every service is skipped and the script exits 0. Rewrite against the real layout and exit non-zero when nothing was restored.

- [ ] Nextcloud dumps in `/mnt/cache/appdata/nextcloud-dump` are not in any archive; the backup-appdata.sh comment is false. Add that path to the plugin's includeFiles.

- [ ] Offsite copy would ship every secret in cleartext: `extra_files.tar.gz` contains `.env`, `generated.env`, `.env.docker`, `configs/`; the flash zip contains Tailscale state and SSH host keys. Require an rclone `crypt` remote (assert in backup-appdata.sh) before `BACKUP_REMOTE` is set.

- [ ] backup-appdata.sh prune uses `find -maxdepth 2` with no `-mindepth`, so hand-placed archives under `/mnt/user/backups/appdata` get deleted; the `.checksums` written are never read. restore-appdata.sh does not stop `nextcloud-cron` when restoring `nextcloud` though both bind the same directory.

## P1 — Access Control

- [ ] Tailnet membership is the only credential on the box: Tailscale SSH is enabled (RunSSH: true), OpenSSH is off. The *arr services use `AuthenticationRequired=DisabledForLocalAddresses` and see the Docker gateway as the client, so no UI behind Tailscale asks for a password. Tautulli web auth is off; SAB has no username. Fix: restrict the SSH grant to the MacBook (consider check mode), switch the *arrs to `Enabled`.

- [ ] LAN direct routing reaches "loopback-only" containers: FORWARD policy ACCEPT, `DOCKER-USER` empty, and Docker accepts a published port from any interface. Any LAN host that adds a route for 172.16.0.0/12 via the Unraid IP reaches Ollama :11434 (no auth) and every UI. Fix: persist `iptables -I DOCKER-USER -i br0 -d 172.16.0.0/12 -j DROP` (User Script at array start), verify from a LAN host.

- [ ] Unraid GUI is plain HTTP on the LAN (`USE_SSL="no"`); root password crosses the wire in clear. Enable SSL (self-signed or Unraid's cert).

- [ ] No container hardening anywhere: no `cap_drop`, no `no-new-privileges`, no pids limits. Gluetun's control server on :8000 is reachable from the downloaders network with default role.

- [ ] Radarr logged three Auth-Failure attempts for user `root` from the iPhone (100.72.171.75) on 2026-08-26. Informational; confirm it was you.

## P2 — Things That Will Bite

- [ ] claudecoach runs with `COACH_SHADOW_MODE=0` (live writes to Garmin and Calendar) since 2026-08-29; TODOS.md still says seven clean shadow nights first. Confirm which is intended and fix the other.

- [ ] Tautulli was never connected to Plex: `pms_ip = 127.0.0.1` (Plex is a different container), the API returns an error, logs say "no token provided". Configure it against `plex:32400` or remove it.

- [ ] Stale static address `192.168.71.99/24` on br0 from an old subnet (`network.ini IPADDR:0`), with nginx and smbd bound to it. Remove in Network Settings.

- [ ] The host is on DHCP with no visible reservation while `PLEX_LAN_IP` / `ADVERTISE_IP` hardcode 10.0.0.123. On Aug 13-14 the one cabled NIC (eth1) flapped 14 times, the lease expired 17 times and the host fell back to a self-assigned address; that caused about 6,400 Gluetun VPN restarts and DNS failures in every container. Set a static IP or reservation; the four-port bond has one cable.

- [ ] Host resolvers are Comcast's directly with no local cache; the Aug 13 outage cascaded into every container. Consider a local resolver.

- [ ] disk3 (`/dev/sda`, ST6000NM0034 Z4D1W322) reports 37 grown defects and 2,804 non-medium errors; every other drive reads 0. Single parity. Watch it, plan a replacement.

- [ ] Unraid is `7.3.0-beta.2` on the box holding non-re-sourceable data; `7.4.0-beta.1` is being offered. Decide on a stable channel.

- [ ] Memory ceilings in compose sum to 34.75 GB (38.75 after the SAB change) on a 31 GB box with no swap; claudecoach has no ceiling. docs/operations.md and decisions.md still say 30.75.

- [ ] coach (chess): lc0 hit CUDA out-of-memory three times and logged 1,210 "CUDNN Runtime version mismatch" warnings; the third GPU tenant is already losing the VRAM fight. 6 GB RAM limit and 4 GB engine hash for a 256-game library is oversized.

- [ ] Ollama: `OLLAMA_CONTEXT_LENGTH=4096` in compose while claudecoach requests `num_ctx=16384`; alternating with actual-ai (4096) forces a runner reload each switch. Fix: align contexts (16384 is the largest and keeps claudecoach happy).

- [ ] SABnzbd `inet_exposure = 0` with empty `local_ranges`: the iPhone (Chrome) was refused twice on 2026-08-30 via svc:sab while the MacBook browser works. Investigate why before changing; `local_ranges = 100.64.0.0/10` is the knob.

- [ ] NZBGeek is the single indexer and Newsdemon the single Usenet provider with no fill server; any limit or outage stalls the pipeline. Prowlarr stats since Aug 12: 6,154 RSS queries, 68 searches, 136 grabs.

- [ ] `data` share is cache=yes with an hourly mover: every download lands on SSD then hops to the array; the mover created the root-owned dirs behind July's 86,000 failed-import log lines. Consider cache=no for `data` (incomplete already has its own SSD share).

- [ ] SAS drives never spin down: `sdspin`/`hdparm` cannot standby SAS behind the PERC. `sg_start` and `sdparm` are installed; the community 'SAS Spindown' plugin (doron) wraps `sg_start --stop` for exactly this. Install it or accept 24/7 spinning.

- [ ] Nextcloud: no calendar/contacts apps installed, only the admin user, no `maintenance_window_start`, HSTS header missing, mimetype migration pending (`occ maintenance:repair --include-expensive`), 67 MB of data.

- [ ] actual-ai has been in dryRun since 2026-07-30 and has found 0 uncategorized transactions on every run. (Left alone on purpose.)

## P3 — Script Bugs (from Static Review)

- [ ] `setup-fan-control.sh` writes a boot script whose first command is `racadm`, which is not installed on the box (neither is ipmitool); the script exits 127 at every array start.

- [ ] `generate-configs.py` / `bootstrap.py` write `.env.docker` raw; compose interpolates `$`, so a human-typed secret containing `$` (e.g. `ACTUAL_PASSWORD`) is mangled. Escape `$` as `$$`.

- [ ] `update-stack.sh:89` `EXPECT_SVCS=$(compose config --services | tr ...)` under `set -e -o pipefail` dies before its own error message.

- [ ] `sync-tailscale-services.py --prune` deletes every `svc:` on the tailnet not in SERVICES, including other hosts'; hostname matched as a substring; one parser still uses `split("#")`.

- [ ] `dedupe-hardlinks.py` globs `/mnt/disk*`, which matches `/mnt/disks` (Unassigned Devices).

- [ ] `verify-stack.sh` docker.img loop-file check is meaningless in folder mode; JSON passed via env var breaks above 128 KiB.

- [ ] `bootstrap.py` pip-installs into `/tmp` on every run; `generate-configs.py` still whitelists `mediaserver.local`; `PLEX_SERVER_NAME` is prompted for but unused.

- [ ] `setup-unraid.sh:136` writes `shareHardLinks=yes`, which is not an Unraid key (the tunable is `fuse_useino`); lines 427/480 print the old schedules (1st 3am collides with parity check).
